# ADR 0002 — The name, the colours and the identifiers that never change

- **Date:** 2026-11-04
- **Status:** accepted
- **Maintainer:** [@sagheerys](https://github.com/sagheerys)

## Context

The app needed a name and a look of its own. The maintainer asked for an
English name that says "video", a blue or red accent, and a white ground by
day with a black one by night.

Short English words in this category are crowded: "Haul", "Pluck", "Stash"
and "Vidrop" each already name several yt-dlp front ends, Play Store apps or
products (ViDrop for macOS, VidDrop on Google Play, vidhaul.com, vidlasso.com,
vidstash.io, the SnagVid site, among others). Every candidate was checked
against GitHub repositories and user names, the two app stores through web
search, npm, PyPI and the `.com`/`.app`/`.io` domains.

## Decision

1. **Name: Vidhoist** (vid + hoist, the load lifted to you). At the time of
   the decision it had no GitHub repository or user, no app in either store,
   no npm or PyPI package, and `vidhoist.com`, `.app` and `.io` were
   unregistered. Runner-up: Vidpluck.
2. **Accent: blue**, `#2457D6` by day and `#7FA3FF` by night (deep, soft and
   ink derivatives in `palette.dart`). Blue collides with none of the state
   colours; red would have sat next to "error" and "favourite".
3. **Grounds:** white `#FFFFFF` by day, black `#000000` by night, with lifted
   cards (`#121212`) so hairlines still read. The espresso ink `#2B211B` is
   kept so the white does not go cold.
   **Amended 2026-11-06:** white cards on a white ground glared and
   the cards had only a hairline to stand on. The day ground is now a soft
   stone `#F2F1EE` under white `#FFFFFF` cards, the way grouped lists lift
   their rows; `palette_ground_test` holds the step between them.
4. **One palette for both apps.** `liteDay/liteNight` are aliases of
   `superDay/superNight`, names kept from the code's earlier shape; there
   are no per-app accents.
5. **The mark**: a tile, a cream plate
   with film perforations, and a window whose title bar is the accent. The
   glyph is a download arrow landing in a tray. Windows uses the espresso
   tile; Android uses the accent tile with the glyph cut out of the plate.
   Everything is generated by `tool/icons/vidhoist_kit.py`.
6. **Fixed for good at the first release:** `applicationId`
   `com.yasir.vidhoist`; `DesktopIdentity.displayName` `'Vidhoist'`, from which
   `%APPDATA%\Vidhoist` is derived; the installer's `AppIdGuid`
   `E0FBCB9C-889B-404E-AB5A-156466DC8CE4`; the link scheme `vidhoist://`;
   the download folder `Download/Vidhoist`.

## Consequences

- A rename after the first release would strand users' data folders and
  break the installer's upgrade path, as `identity.dart` warns.
  `identity_test.dart` holds the runner's ProductName to the display
  name.
- The availability check is a snapshot of 2026-11-04 and is not a trademark
  search. Before the public release, the maintainer registers at least
  `vidhoist.app` and rechecks the stores.

## Amendment 2026-11-11: the mark is a folded ribbon

Point 5 no longer holds. The maintainer asked for a mark of the app's own,
with the hint "a V mixed with downloading", and chose from three boards of
mockups: first the folded film ribbon out of seven concepts, then its polished cut,
then the cut with a clear gap along the fold instead of an outline.

The mark is a strip of film folded into the letter V. The front arm carries
four perforations down its outer edge; the back arm is the second colour and
stops a hair short of the front one. Light ground: ink and the accent.
Windows: the espresso tile, cream and the night accent `#7FA3FF` (the day
accent is too dim on espresso). Android: the accent tile, cream and a soft
blue `#BCCDF5`. Below 24 px the perforations go and the gap widens. The
tile's plate and window are gone; the film perforations remain. Still
generated by
`tool/icons/vidhoist_kit.py`. No trademark search was made for the shape:
it joins the recheck this ADR already asks for before the public release.

## Amendment 2026-11-09: the phone's folder is `Download/VidHoist`

The maintainer asked for the folder to be spelled as the app is shown. The
app was not public yet, so only test phones held data. Android's shared
storage ignores letter case when it opens a folder, but **lists a
folder's files only under the spelling on disk**: the first build scanned
`VidHoist` while a test phone still said `Vidhoist`, and the library
showed no downloads at all, files untouched. At every start the phone app
tries the rename through a spare name, then reads the spelling the disk
really has and uses it (`phoneMediaDir`, settled before runApp), and
rewrites any saved path to that spelling, at start and after every
restore, since the library keys favourites, titles, covers and each
clip's link by the file's path (`media_folder_rename.dart`). Android
refused the rename on that phone ("Operation not permitted": the
folder holds an earlier install's files), so it stays `Vidhoist` there
until renamed in a file manager, which the next start then follows. A memory card, when one is
chosen in Settings › Downloads, gets a folder of the same name. Windows
keeps `%APPDATA%\Vidhoist`: Windows ignores case too, and nothing there is
keyed by that path's spelling in a way a user sees.
