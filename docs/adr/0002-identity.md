# ADR 0002 — The name, the colours and the identifiers that never change

- **Date:** 2026-11-04
- **Status:** accepted
- **Owner:** Yasir Sagheer

## Context

The fork needed a name and look of its own, close enough to the parent that
the design system transfers untouched, distinct enough that nobody mistakes
one for the other. The owner asked for an English name that says "video", a
blue or red accent, and a white ground by day with a black one by night.

Short English words in this category are crowded: "Haul", "Pluck", "Stash"
and "Vidrop" each already name several yt-dlp front ends, Play Store apps or
products (ViDrop for macOS, VidDrop on Google Play, vidhaul.com, vidlasso.com,
vidstash.io, the SnagVid site, among others). Every candidate was checked
against GitHub repositories and user names, the two app stores through web
search, npm, PyPI and the `.com`/`.app`/`.io` domains.

## Decision

1. **Name: Vidhoist** (vid + hoist, the load lifted to you). At the time of
   the decision it had no GitHub repository or user, no app in either store,
   no npm or PyPI package, and `vidhoist.com`, `.app` and `.io` were
   unregistered. Runner-up: Vidpluck.
2. **Accent: blue**, `#2457D6` by day and `#7FA3FF` by night (deep, soft and
   ink derivatives in `palette.dart`). Blue collides with none of the state
   colours; red would have sat next to "error" and "favourite".
3. **Grounds:** white `#FFFFFF` by day, black `#000000` by night, with lifted
   cards (`#121212`) so hairlines still read. The espresso ink `#2B211B` is
   kept so the white does not go cold.
   **Amended 2026-11-06 (owner):** white cards on a white ground glared and
   the cards had only a hairline to stand on. The day ground is now a soft
   stone `#F2F1EE` under white `#FFFFFF` cards, the way grouped lists lift
   their rows; `palette_ground_test` holds the step between them.
4. **One palette for both apps.** `liteDay/liteNight` are aliases of
   `superDay/superNight`. The parent's per-app accents (ember, petrol) are
   gone.
5. **The mark** keeps the parent family's structure: a tile, a cream plate
   with film perforations, and a window whose title bar is the accent. The
   glyph is a download arrow landing in a tray. Windows uses the espresso
   tile; Android uses the accent tile with the glyph cut out of the plate.
   Everything is generated by `tool/icons/vidhoist_kit.py`.
6. **Fixed for good at the first release:** `applicationId`
   `com.yasir.vidhoist`; `DesktopIdentity.displayName` `'Vidhoist'`, from which
   `%APPDATA%\Vidhoist` is derived; the installer's `AppIdGuid`
   `E0FBCB9C-889B-404E-AB5A-156466DC8CE4`; the link scheme `vidhoist://`;
   the download folder `Download/Vidhoist`.

## Consequences

- A rename after the first release would strand users' data folders and
  break the installer's upgrade path, exactly as the parent's `identity.dart`
  warns. `identity_test.dart` holds the runner's ProductName to the display
  name.
- The availability check is a snapshot of 2026-11-04 and is not a trademark
  search. Before the public release, the owner registers at least
  `vidhoist.app` and rechecks the stores.

## Amendment 2026-11-09: the phone's folder is `Download/VidHoist`

The owner asked for the folder to be spelled as the app is shown. The app
was not public yet, so only the owner's phone held data. Android's shared
storage ignores letter case, so `Vidhoist` and `VidHoist` are one folder;
what the spelling changes is the saved text, because the library keys
favourites, titles, covers and each clip's link by the file's path. At
every start, and after every restore, the phone app rewrites any saved
path in the old spelling (`media_folder_rename.dart`), then renames the
folder on disk through a spare name. Android may refuse the rename when
the folder holds files an earlier install left; the app works the same,
and only a file manager still shows `Vidhoist`. A memory card, when one is
chosen in Settings › Downloads, gets a folder of the same name. Windows
keeps `%APPDATA%\Vidhoist`: Windows ignores case too, and nothing there is
keyed by that path's spelling in a way a user sees.
